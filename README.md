# ЭС-чат — открытый чат для проектировщиков электроснабжения

Чат без регистрации: придумал ник и код-пароль — и внутри. Каналы и группы видны всем,
личные сообщения читают только два участника переписки. Всё — и текст, и фото — исчезает
само через 48 часов.

Клиент — обычная статика (HTML + CSS + ES-модуль, без сборки и зависимостей), живёт на
GitHub Pages. Серверная часть — бесплатный проект Supabase (Postgres + политики RLS + Realtime).

## Что умеет

- вход по нику и коду, без почты, телефона и SMS;
- ник закрепляется первым заявлением: второго претендента с тем же ником сервер не пустит,
  и именно поэтому личку видит только тот, кто этот ник придумал;
- каналы (открытые, для всех) и группы (по названию, создаёт любой участник);
- личные сообщения между двумя никами, список собеседников и число писем за 48 часов;
- фото и скриншоты с телефона: кнопка 📎 (камера или галерея), вставка из буфера обмена,
  перетаскивание файла; на устройстве картинка ужимается до ~1600 px и JPEG;
- лента обновляется сама: клиент опрашивает сервер раз в ~2 секунды (открытые комнаты) и раз в
  ~4 секунды личку, на фоновой вкладке реже. Никаких WebSocket-ключей и платных тарифов за это не надо;
- у каждой записи счётчик «осталось N ч», потом запись удаляется безвозвратно;
- список тех, кто заходил за последние 5 минут;
- мобильная вёрстка: 390 px, `100dvh`, безопасные зоны iPhone, поле ввода прижато к низу,
  кнопка отправки не подлезает под клавиатуру.

## Установка (один раз, минут десять)

1. Создай проект на [supabase.com](https://supabase.com) — достаточно бесплатного тарифа.
2. Открой **SQL Editor** и выполни по очереди два файла:
   - [`sql/01-schema.sql`](sql/01-schema.sql) — таблицы, ограничения размера, служебная таблица метёлки;
   - [`sql/02-rpc.sql`](sql/02-rpc.sql) — функции входа/отправки/чтения, права роли `anon`,
     Row Level Security и подключение `chat_message` к Realtime.

   Объектное хранилище Supabase не используется: сжатое фото (`data:`-URL) лежит в самой строке
   сообщения и защищается теми же политиками, что и текст. Зато очистка честная: удалена строка —
   удалено и вложение, осиротевших файлов в бакете не бывает.
3. Скопируй **Project URL** и **anon public key** (Settings → API Keys) в
   [`js/config.js`](js/config.js):

   ```js
   window.ESCHAT = {
     url: 'https://abcdefghij.supabase.co',
     key: 'eyJhbGciOi...',
   };
   ```

   `anon`-ключ публичный: он всё равно виден в коде страницы и ограничен политиками RLS.
   `service_role` и пароль от базы в клиент класть нельзя — с ними защита лички обнуляется.
4. Закоммить `js/config.js`, затем **Settings → Pages → Branch: main, folder: root**.
5. Открой `https://<логин>.github.io/es-chat/` и зарегистрируй первый ник.

Пока `js/config.js` пустой, страница честно показывает инструкцию по подключению и никуда
ничего не отправляет.

### Если в чат никто не заходит

Метёлку `chat_gc()` вызывают сами клиенты (в среднем раз в 4 минуты). Хочется гарантий —
повесь задание на `pg_cron`:

```sql
create extension if not exists pg_cron;
select cron.schedule('eschat-gc', '*/10 * * * *', $$select public.chat_gc()$$);
```

## Что стоит знать про ограничения

- **Код-пароль не восстанавливается.** Забыл ник или код — личка потеряна; это плата за
  «без регистрации». На устройстве данные лежат в `sessionStorage`, то есть при закрытии вкладки
  выходит, и каждый раз нужен свой код.
- **Каналы открыты буквально**: сообщение канала видит любой, кто открыл страницу.
- **Размер вложения** — до ~300 КБ в JPEG (в БД CHECK на 400 000 символов base64). Больше —
  клиент сожмёт сам, не сожмётся — откажет до отправки.
- **Сквозного шифрования нет**: доступ к личке раздают политики базы, а не ключ в браузере,
  поэтому владелец проекта Supabase теоретически может прочитать содержимое. Для настоящего
  E2EE нужна ключевая пара на ник — это отдельный этап.
- **Код хранится как SHA-256 от `ник␟код` без соли**, поэтому 4 символа — это минимум;
  лучше короткая фраза, а не `1234`.

## Локальный запуск и тесты

```bash
python3 -m http.server 4173          # открыть http://127.0.0.1:4173
bash run.sh                          # полный прогон: 13 проверок БД + 27 сквозных проверок клиента
```

`run.sh` поднимает временный PostgreSQL, накатывает `sql/`, запускает эмулятор Supabase
(`tests/mock_supabase.py`, нужные клиенту эндпоинты PostgREST и Realtime-событий) и гоняет
браузеры через Playwright: два ника общаются, третий не читает чужую личку, не свой код не
пускает даже в открытый канал, фото доезжает, зачистка 48 часов работает, мобильный экран
390 px без переполнения. `tests/run.sql` — то же на уровне чистой SQL, без браузера.
